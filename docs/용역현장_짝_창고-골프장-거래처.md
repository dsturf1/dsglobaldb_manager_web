# 용역 현장 짝 — 창고 ↔ 골프장 ↔ 고객사 거래처

> 2026-10-30 · 요청: 투입비(expense mgmt) · 관련: `gdb-request-warehouse-course.md`(작업 보고·재고 요청), `EXTERNAL_API_GUIDE.md` 4-1

## 왜

용역 현장 하나를 앱마다 다른 키로 알고 있었다.

| 앱 | 현장을 아는 키 | 짝을 두던 곳 |
|---|---|---|
| 작업 보고 (dsocr, 동성클로이) | 골프장 `mapdscourseid` | `config/sites.yaml` |
| 재고 (inv mg) | 창고 `whcd` | 재고 DB `wh_courses` 표 |
| 투입비 (expense mgmt) | 현장 id + 창고·고객사 | 현장 설정 |

짝이 세 곳에 따로 있으면 어긋난다. 이제 **글로벌 DB 한 곳**에 둔다.

## 무엇을 어디에

| 레코드 | 필드 | 뜻 | 고치는 곳 |
|---|---|---|---|
| 창고 (`dswarehouses`, `GET /dswarehouse`) | `mapdscourseid` | 이 용역 창고가 속한 골프장. 용역 현장 창고만, **한 골프장에 창고 하나** | 웹 **창고** 화면 → 줄 더블클릭 → 골프장 |
| 골프장 (`dsbaseinfo/common/mapcourse_info.json`, baseinfo · `/dscourse`) | `custcd`, `custName` | 용역 기성 청구 상대(고객사) 거래처. `custcd` 는 거래처 코드(대부분 사업자번호) | 웹 **골프장** 화면 → 수정 → 고객사 거래처 |

찾는 길: `창고.mapdscourseid → 골프장 → 골프장.custcd → 거래처(사업자번호·대표·업태/종목)`

## 바뀐 것

- 웹 `src/DSWarehouse/DSWarehouseTable.jsx` — '골프장' 열, 수정 창에서 골프장 고르기(다른 창고에 이미 있으면 막음).
- 웹 `src/DSMapCourse/CourseEditDialog.jsx` — 고객사 거래처 고르기(이름·별칭·사업자번호 검색, 골프장 분류 먼저). 카드(`DSMapCourse.jsx`)에 표시.
- 웹 `src/DSMapCourse/courseApi.js` — 골프장 목록 읽기(창고 화면이 씀).
- **서버(Lambda)는 그대로.** 창고 저장은 레코드 전체 `put_item`(웹이 받은 레코드에 필드를 더해 보냄), 골프장 저장 `dsoutcourse` 는 보낸 필드만 덮어쓴다(`existing.update`). 이카운트 엑셀 비교는 이카운트 항목만 바꾸고 나머지 필드는 둔다.

## 쓰는 앱

- **투입비**: ⚙️ 현장 셋업에서 골프장을 고르면 창고·고객사(사업자번호·대표·업태/종목)를 여기서 가져온다. 서류 양식 칸 `{{고객사사업자번호}}` 등.
- **재고·작업 보고**: 아직 각자 짝 표를 쓴다. 옮길 때는 `GET /dswarehouse` 의 `mapdscourseid` 를 먼저 보고, 없으면 지금 표로.

## 조심

- `mapcourse_info.json` 은 파일 하나다. BaseInfo 노트북 업로드나 baseinfo `POST`(replace) 로 **통째로 올리면** `custcd`·`custName` 이 지워질 수 있다. 올리기 전 지금 파일을 받아 두 필드를 살릴 것.
- 아직 외부 앱용 창고 부분 수정 API(`POST /dswarehouse/update`)는 없다. 고치는 것은 웹에서만.
