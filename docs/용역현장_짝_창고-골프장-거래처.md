# 용역 현장 짝 — 창고 ↔ 골프장 ↔ 고객사 거래처

> 2026-10-30 · 요청: 투입비(expense mgmt) · 관련: `gdb-request-warehouse-course.md`(작업 보고·재고 요청), `EXTERNAL_API_GUIDE.md` 4-1

## 왜

용역 현장 하나를 앱마다 다른 키로 알고 있었다.

| 앱 | 현장을 아는 키 | 짝을 두던 곳 |
|---|---|---|
| 작업 보고 (dsocr, 동성클로이) | 골프장 `mapdscourseid` | `config/sites.yaml` |
| 재고 (inv mg) | 창고 `whcd` | 재고 DB `wh_courses` 표 |
| 투입비 (expense mgmt) | 현장 id + 창고·고객사 | 현장 설정 |

짝이 세 곳에 따로 있으면 어긋난다. 이제 **글로벌 DB 한 곳**에 둔다.

## 무엇을 어디에 (2026-10-31 바뀜 — 방제작업코스가 원본)

**방제작업코스(GCxxx) 한 줄이 용역 현장 하나의 원본**이다. 골프장·창고 화면은 GC 를 골라 거기 값을 불러오고, GC 에 값이 없을 때만 직접 고른다.

| 레코드 | 필드 | 뜻 | 고치는 곳 |
|---|---|---|---|
| **방제작업코스** (`dsbaseinfo/common/dsworkcourse_info.json`, baseinfo `GET/PUT /dscourse_info`) | `mapdscourseid` | 맵코스(골프장) | 웹 **방제작업코스** → 수정 → mapdscourseid (이름으로 고름) |
| | `custcd`, `custName` | 용역 기성 청구 상대(고객사) 거래처. `custcd` = 거래처 코드(대부분 사업자번호) | 같은 창 → 고객사 거래처 |
| | `outwhcd` (+ 이름 `outwarehouse`) | 용역창고. 약품·방제 기본정보는 이름으로 쓰므로 이름도 같이 둔다 | 같은 창 → 용역창고 (창고 목록에서 고름) |
| 골프장 (`mapcourse_info.json`, `/dscourse`) | `dscourseids` | 이 골프장의 GC | 웹 **골프장** → 수정 → 방제작업코스 |
| | `custcd`, `custName` | GC 에 고객사가 있으면 **GC 값을 불러와 저장**(읽기 전용 표시). 없을 때만 직접 고름 | 같은 창 |
| 창고 (`dswarehouses`, `/dswarehouse`) | `dscourseids` | 이 용역 창고의 GC (한 GC 에 창고 하나) | 웹 **창고** → 줄 더블클릭 → 방제작업코스 (용역창고 이름이 같은 GC 를 먼저 제안) |
| | `mapdscourseid` | GC 에 맵코스가 있으면 **GC 값을 불러와 저장**. 없을 때만 직접 고름 | 같은 창 |

찾는 길(앱): `골프장 MGC → mapdscourseid 가 그것인 GC → GC.custcd(거래처)·GC.outwhcd(창고)`. GC 에 없으면 골프장.custcd · 창고.mapdscourseid.
골프장·창고에 적힌 값은 GC 에서 내려받은 사본이다 — GC 를 바꾸면 골프장·창고 창을 한 번 열어 저장하거나 `expense mgmt/tools/seed_gdb_links.py --apply` 로 다시 내려보낸다.

## 바뀐 것

- 웹 `src/DSWorkCourse/WorkCourseEditDialog.jsx` — mapdscourseid 를 맵코스 이름으로, 용역창고를 창고 목록에서(outwhcd 저장), 고객사 거래처 고르기. 목록에 '고객사' 열. `workCourseApi.js` — GC 목록 읽기.
- 웹 `src/DSMapCourse/CourseEditDialog.jsx` — 방제작업코스 고르기 → 고객사를 GC 에서. 카드에 GC 표시.
- 웹 `src/DSWarehouse/DSWarehouseTable.jsx` — 방제작업코스 고르기 → 골프장을 GC 에서. GC 도 창고 하나에만.
- 웹 `src/DSCustomer/CustomerPicker.jsx` — 거래처 고르기(공용).
- **서버(Lambda)는 그대로.** GC 저장은 목록 전체 PUT(웹이 받은 목록에 필드를 더해 보냄), 창고 저장은 레코드 전체 `put_item`, 골프장 저장 `dsoutcourse` 는 보낸 필드만 덮어쓴다.

## 쓰는 앱

- **투입비**: ⚙️ 현장 셋업에서 골프장을 고르면 창고·고객사(사업자번호·대표·업태/종목)를 여기서 가져온다. 서류 양식 칸 `{{고객사사업자번호}}` 등.
- **재고·작업 보고**: 아직 각자 짝 표를 쓴다. 옮길 때는 `GET /dswarehouse` 의 `mapdscourseid` 를 먼저 보고, 없으면 지금 표로.

## 조심

- `dsworkcourse_info.json` 도 파일 하나이고 웹이 **목록 전체를 PUT** 한다. 두 사람이 동시에 고치면 나중 저장이 앞 저장을 지운다. BaseInfo 노트북으로 올릴 때도 `custcd`·`custName`·`outwhcd` 를 살릴 것.
- `mapcourse_info.json` 은 파일 하나다. BaseInfo 노트북 업로드나 baseinfo `POST`(replace) 로 **통째로 올리면** `custcd`·`custName` 이 지워질 수 있다. 올리기 전 지금 파일을 받아 두 필드를 살릴 것.
- 아직 외부 앱용 창고 부분 수정 API(`POST /dswarehouse/update`)는 없다. 고치는 것은 웹에서만.
