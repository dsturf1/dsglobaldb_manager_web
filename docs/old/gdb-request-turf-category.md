# 글로벌 DB 작업 요청 — 거래처 분류에 '잔디농장' 추가

> 요청: 재고 관리(inv mg) 프로젝트 · 2026-10-08
> 대상: 글로벌 DB 프로젝트 (dsglobaldb_manager / `/dscustomer` API·웹)
> 관련: `EXTERNAL_API_GUIDE.md` 4.2 거래처 필드(`category`), 6.2 거래처 추가, 6.4 부분 수정

## 1. 왜 필요한가

잔디는 농장에서 사서 바로 골프장에 판다. 재고 관리 프로젝트에 잔디 전용 창고(본사잔디 101)와 잔디방 봇을 만들었다.
잔디 구매처(농장)를 일반 매입처와 구분해 두면 다음이 쉬워진다.
- 잔디 매입·매출 통합 화면과 봇이 구매처를 고를 때 농장만 후보로 보기
- 견적 등 다른 앱에서도 잔디 농장을 따로 거르기

지금 `category`는 `골프장` `매입처` `매출처` `기타`만 받는다. `/dscustomer/update`로 `잔디농장`을 보내면 400이 난다:
`category 는 골프장, 매입처, 매출처, 기타 중 하나여야 합니다`.

## 2. 요청

1. 거래처 `category` 허용 값에 **`잔디농장`**을 추가한다. 적용할 곳:
   - `POST /dscustomer/update`의 `set.category` 검사
   - `POST /dscustomer/create`의 `category` 검사
   - 글로벌 DB 웹의 거래처 분류 선택 목록, 목록 화면의 분류 필터
2. `EXTERNAL_API_GUIDE.md` 4.2(`category` 예)와 6.2(거래처 추가 표)에 `잔디농장`을 넣는다.
3. `GLOBALDB_API_CHANGELOG.md`에 한 줄 남긴다. 읽는 앱이 분류 값을 고정 목록으로 검사한다면 새 값을 받아들여야 하기 때문이다.

이카운트 거래처에는 같은 분류가 없다. 글로벌 DB에서만 쓰는 분류여도 된다(이카운트 동기화 대상 아님).

## 3. 반영되면 재고 프로젝트에서 할 일

반영되면 재고 프로젝트가 아래 거래처의 `category`를 `잔디농장`으로 바꾼다(`/dscustomer/update`, 키 globaldb-inv).
이카운트 잔디 기록과 잔디 매입·매출 통합 엑셀의 '매입' 거래처다.

| 별칭 | 거래처 | 코드 | 지금 분류 |
|---|---|---|---|
| 빛그린 | 빛그린스포츠잔디영농조합법인 | 1868800210 | 기타 |
| 그린뷰 | 그린 뷰 | 2319005390 | 기타 |
| 3.8잔디 | 3.8농장 | 1639501913 | 기타 |
| 명성잔디 | 농업회사법인 명성잔디 주식회사 | 8138101006 | 기타 |
| 토아 | 농업회사법인 (주)토아 | 5958702486 | 기타 |

## 4. 같이 봐 주면 좋은 것 (데이터)

같은 업체로 보이는 거래처가 두 개씩 있어 별칭을 붙이지 못했다 (`aliasTaken`):
- `그린뷰` (1352158856) ↔ `그린 뷰` (2319005390)
- `명성잔디` (876) ↔ `농업회사법인 명성잔디 주식회사` (8138101006)

이카운트 잔디 기록은 뒤쪽(사업자번호 코드)을 쓴다. 앞쪽이 안 쓰는 옛 코드라면 `active: N`으로 바꿔 주면, 별칭 '그린뷰'·'명성잔디'를 뒤쪽에 붙일 수 있다.

## 5. 다 됐는지 확인할 것

1. `POST /dscustomer/update` `{set: {category: "잔디농장"}}`가 200이다.
2. 새 거래처를 `category: "잔디농장"`으로 만들 수 있다.
3. 글로벌 DB 웹 거래처 화면에서 분류 '잔디농장'을 고르고 거를 수 있다.
4. 가이드와 변경 이력에 반영됐다.
