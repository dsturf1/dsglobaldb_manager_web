# 글로벌 DB 시스템 구성도

> 2026-11-03 기준 · 대상: 이 저장소(`dsglobaldb_manager`)를 고치거나 운영하는 사람
> 화면 쓰는 법은 [사용법.md](사용법.md), 외부 앱용 API 는 [EXTERNAL_API_GUIDE.md](EXTERNAL_API_GUIDE.md), 바뀐 내역은 [GLOBALDB_API_CHANGELOG.md](GLOBALDB_API_CHANGELOG.md)

글로벌 DB 는 동성그린의 **공통 기준 데이터**(약품·기타 코드, 거래처, 창고, 인력, 장비, 골프장·방제 기본정보)를 한 곳에 두고,
웹에서 관리하며, 재고·견적·작업 보고·투입비 같은 다른 앱이 API 로 읽어 쓰게 하는 시스템이다.

| `dsworkforceDynamoDB` | `/dsworkforce` | 없음 | `dsworkforce` |
| `dsequipmentDynamoDBV2` | `/equipment` | 없음 | `dsequipmentsV2` |
| `dsMaintenanceDetail`, `dsmaintenanceDynamoDBV2` | `/maintenanceV2`, `/maintenance` | 없음 | `dsmaintenance_recordsDetail`, `dsmaintenance_records` |

| **`dsglobaldbCreate`** | 아래 표 | 경로마다 | `dschemicals` `dscustomers` `dswarehouses` `dschemical_history` `dscustomer_history` `dsglobaldb-bot`, S3 `dsbaseinfo` |
| **`dsglobaldbBot`** | `POST /tgbot` (텔레그램 webhook) + Lambda 직접 호출 | secret_token 헤더 | `dsglobaldb-bot`, SSM 토큰, S3 증빙 읽기 |

`dsglobaldbCreate` (`AWS/Lambda/dsglobaldbCreate/lambda_function.py`) — **안전한 쓰기는 모두 여기**:

| 경로 | 하는 일 | 인증 |
|---|---|---|
| `POST /dschemical/create`, `POST /dscustomer/create` | 등록 요청으로 추가. 코드는 서버가 정하고 덮어쓰지 않음. 거래처는 증빙 자동 등록 판단 | **`x-api-key` + `request` 블록 필수** (Lambda 가 확인: 없으면 403/400) |
| `GET /dschemical/next-code` | 다음 약품 코드 미리보기 | 없음 |
| `POST /dswarehouse/create` | 창고 추가 (코드·이름 중복 409) | 없음 |
| `POST /{dschemical·dscustomer}/update`, `/alias` | 부분 수정 · 별칭 (동시 수정 409, 이력) | `x-api-key` (사용량 계획 `globaldb-write`) |
| `GET /{dschemical·dscustomer}/history` | 변경 이력 50건 | 없음 |
| `POST /dscustomer/evidence-upload` | 증빙 파일 올릴 주소 (S3 presigned PUT 10분) | `x-api-key` |
| `GET /regrequests` | 등록 요청 목록 | `x-api-key` |
| `POST /{dschemical·dscustomer}/review` | **닫힘** — 모든 외부 키 403 | — |
| `GET/POST /regreview` | 웹 승인 (승인자만) | Cognito 권한 부여자 `dsglobaldb-cognito` |
| `GET/POST /gdbsettings` | 웹 설정: 승인자·텔레그램 연결 | Cognito |
| `/internal/pending·request·review·approvers·redeem` | 봇 전용 (API Gateway 에 없는 경로, Lambda 직접 호출로만) | — |

API 키는 앱마다(`globaldb-inv`, `globaldb-quote`, `globaldb-web`). Lambda 는 환경 변수 `KEY_APPS`(키 값의 sha256 → 앱)로 요청한 앱을 정한다. 그 밖의 환경 변수: `GDB_OWNER_EMAILS`(슈퍼관리자), `GDB_BOT_FUNCTION`, `GDB_BOT_USERNAME`, `BOT_TABLE`.

`dsglobaldbBot` (`AWS/Lambda/dsglobaldbBot/lambda_function.py`): `@dsgreen_gdb_bot`. 직접 호출 동작 `card`(승인 카드), `decided`(카드를 결정 문구로), `morning`(EventBridge `dsglobaldb-bot-morning`, 매일 08:00 KST 요약). 환경 변수 `TOKEN_PARAM`(SSM `/dsglobaldb/bot/token`), `WEBHOOK_SECRET`, `GDB_OWNER_TG`(비상용 승인자 번호), `CORE_FUNCTION`, `BOT_TABLE`, `WEB_URL`.

### 3.1 등록 요청과 승인 (2026-10-12~)

```
 재고·견적 봇/웹 ── create(+request, +evidence) ──▶ dsglobaldbCreate ── 코드 발급
                                                    │  증빙 거래처: regStatus approved(자동), ecountStatus pending
                                                    │  그 밖     : regStatus requested,       ecountStatus pending
                                                    │  글로벌 DB 웹: 둘 다 approved (승인 없음)
                                                    ▼ (승인 대기면 비동기 호출)
                                             dsglobaldbBot ── 승인자에게 카드 (텔레그램)
                                                    │
     승인자: 봇 카드 [✅ 승인 (등록 + 이카운트)] [❌ 반려] [🚫 이카운트 제외]  또는  웹 '등록 요청' 버튼
                                                    ▼
                                    regDecision 기록 → 봇 카드를 결정 문구로
                                                    ▼
     요청한 앱이 GET /regrequests?app=<자기>&changedSince= 로 결과를 받아 요청자에게 알림
                                                    ▼
     사람이 이카운트에 등록 → 웹 [이카운트 비교 → 등록 완료로 반영] → ecountSyncedAt
```

- 필드: `regStatus`(등록 승인) · `ecountStatus`(이카운트 등록 승인) · `regRequest`(요청 정보, `app` 은 키로 정함) · `regEvidence` · `regDecision`. 없으면 이전 데이터로 보고 `approved`.
- **승인 전(`requested`)에는 앱이 그 코드를 쓰지 않는다.** 예외: 견적의 거래처는 승인 대기에도 견적에 쓴다. 반려하면 `active = N`.
- 승인자 = **슈퍼관리자**(`GDB_OWNER_EMAILS`, 웹에서 못 바꿈) + 웹 **설정**에서 추가한 승인자. 텔레그램은 설정의 한 번만 쓰는 링크(`t.me/dsgreen_gdb_bot?start=<코드>`)로 연결.
- 자세한 규칙: [old/gdb-request-registration-queue.md](old/gdb-request-registration-queue.md) (요청서, 6차 개정까지 끝남), API 는 가이드 5.1·6.6.

### 3.2 이카운트 연동

| 무엇 | 방향 | 방법 |
|---|---|---|
| 품목 | 이카운트 → 글로벌 DB | `(E0-0)` 노트북이 OpenAPI 로 S3 에 올림 → 웹 [이카운트 비교 → 서버 데이터 불러오기] 또는 엑셀 ESA009M 올리기 → [선택 추가] |
| 거래처 | 이카운트 → 글로벌 DB | 엑셀 ESA001M → 웹 [이카운트 엑셀 비교] (신규·변경 반영) |
| 창고 | 이카운트 → 글로벌 DB | 엑셀 ESA005M → 웹 [이카운트 엑셀 비교] |
| 글로벌 DB 에서 만든 것 | 글로벌 DB → 이카운트 | 자동 아님. [이카운트 미등록] 탭 엑셀을 받아 사람이 이카운트에 등록 → [등록 완료로 반영] (`ecountSyncedAt`) |
| 여기서 고친 이카운트 거래처 이름 등 | 표시만 | `ecountDirtyFields` — 이카운트에도 고칠 것 |

실시간 연동은 없다. 이카운트 업로드 파일에는 `origin = ecount` 또는 `ecountSyncedAt` 있는 것만 넣는다.

## 6. 조심할 점

- **전체 덮어쓰기 경로**: `/dschemical`·`/dscustomer`·`/dswarehouse` 의 PUT/POST, `/dscourse_info`, baseinfo PUT 은 받은 레코드(또는 목록)로 통째로 바꾼다. 화면을 오래 열어 두었다 저장하면 그사이 다른 곳의 수정(승인 결정 등)을 지울 수 있다. 외부 앱은 create·update·alias 만 쓴다. 웹의 [등록 완료로 반영]은 저장 직전에 최신 레코드를 다시 읽는다.
- **창고 부분 수정 API 가 없다** (`POST /dswarehouse/update` 없음). 창고·골프장·방제작업코스는 웹에서만 고친다.
- **create 키 필수**: 약품·거래처 create 는 키와 `request` 가 없으면 403/400. 창고 create·next-code·조회는 키 없이 된다.
- 응답은 항상 HTTP 200 + `statusCode` (API 키 오류 403 만 예외).
- 봇 webhook 은 `WEBHOOK_SECRET` 이 맞아야 처리한다. 토큰을 바꾸면 `(L1-7)` 를 다시 돌려 SSM·webhook 을 맞춘다.
